# Telegram-бот — обновлённая версия

## 🆕 Архитектура: теперь ДВА бота

Раньше спонсоры добавляли администратором в свой канал того же самого бота,
который раздаёт читы. Теперь это разделено на два отдельных бота (два
отдельных Telegram-аккаунта, два отдельных сервиса на Render):

| | `bot.py` (основной бот) | `checker_bot.py` (чекер-бот) |
|---|---|---|
| Что делает | Раздаёт читы, админ-панель, спонсоры, тексты | Только проверяет подписку через `getChatMember` |
| Кто с ним общается | Обычные пользователи и админы в Telegram | Только основной бот, по HTTP (не через Telegram) |
| Кого добавляют в канал спонсора | Никого | Его — администратором |
| Есть ли у него контент/читы | Да | Нет вообще |

**Зачем так делать:** спонсору спокойнее дать права администратора в своём
канале нейтральному служебному боту без читов и контента, чем боту, у которого
на аватарке и в названии — раздача читов. Плюс так безопаснее: если основной
бот когда-нибудь скомпрометируют, у него всё равно не будет прав администратора
ни в одном канале.

Общаются они между собой не через Telegram, а напрямую по HTTP: у чекер-бота
есть небольшой веб-сервер (тот же самый aiohttp, что раньше использовался
только для health-check) с тремя адресами:

- `GET /check_member?chat_id=&user_id=&secret=` — подписан ли пользователь на канал;
- `GET /status?chat_id=&secret=` — является ли сам чекер-бот админом канала (используется
  один раз при подключении нового спонсора, чтобы убедиться, что бот реально добавлен);
- `GET /whoami` — какой у чекер-бота @username (нужно основному боту для текста инструкции).

Все запросы защищены общим секретом `CHECKER_SECRET` (задаётся одинаковым в
обоих сервисах) — без него любой посторонний, кто узнает адрес чекер-бота,
смог бы дёргать `/check_member` и проверять чужие подписки.

**Для пользователя и спонсора визуально почти ничего не меняется** — тот же
процесс подключения спонсора (кнопка «🔗 Добавить свою ссылку» / `/give`),
просто на шаге «добавьте бота администратором» теперь нужно добавлять другого,
служебного бота, и в самом конце основной бот через HTTP спрашивает у него
разрешения, а не проверяет сам.

## Что изменилось по сравнению с исходником

- **Исправлен баг** в `ThrottlingMiddleware`: было `def init` / `def call` (не сработало бы вообще), стало `__init__` / `__call__`.
- **Готов к деплою на Render как Web Service**: бот поднимает лёгкий HTTP-сервер (aiohttp) на порту из переменной `PORT` и отвечает `OK` на `/` и `/health`. Это нужно, чтобы Render не считал сервис "мёртвым", и чтобы было куда стучаться UptimeRobot'у.
- **Все настройки — через переменные окружения** (токен, админы и т.д. больше не хардкодятся в коде — см. `.env.example`).
- **Множественные админы**: таблица `admins` в БД, команда/кнопка «Добавить админа» (по ID или пересланному сообщению). Исходные ID из `ADMIN_IDS` становятся супер-админами (их нельзя удалить).
- **Фото и гифки для читов**: при добавлении чита теперь можно прислать не только текст/файл, но и фото или GIF — бот сам определит тип и потом корректно отправит его пользователю.
- **Красивое инлайн-меню**:
  - Пользователь видит приветствие с картинкой/гифкой и инлайн-кнопками «📢 Канал» / «🛟 Поддержка».
  - Админ видит инлайн-панель: «➕ Добавить чит», «📋 Список читов», «👤 Добавить админа», «🗒 Список админов», «❌ Закрыть».
  - Список читов — это инлайн-кнопки с удалением по одному клику + подтверждение перед удалением.
- **Команды через "/"**: у админов в интерфейсе Telegram появляется меню команд (`/start`, `/menu`, `/add`, `/list`, `/delete`, `/addadmin`, `/admins`) — можно вводить и кликом, и вручную. У обычных пользователей в меню только `/start`.

## Структура файлов

```
bot.py                — основной бот (читы, админ-панель, спонсоры)
checker_bot.py         — чекер-бот (только проверка подписки, отдельный сервис)
requirements.txt       — зависимости (общие для обоих ботов)
Procfile                — команда запуска для платформ, которые не используют render.yaml
render.yaml             — blueprint для деплоя ОБОИХ сервисов одной кнопкой
.env.example            — какие переменные окружения нужны каждому боту
welcome.png / .gif      — (добавьте сами) картинка/гифка приветствия, рядом с bot.py
```

## Деплой на Render (два Web Service из одного репозитория)

Оба бота лежат в одном GitHub-репозитории, но на Render это будут **два разных
сервиса**, каждый со своим токеном.

### Вариант А — одной кнопкой через render.yaml

1. Залейте все файлы в GitHub-репозиторий (плюс `welcome.png`/`welcome.gif`, если нужно).
2. На [render.com](https://render.com) → **New** → **Blueprint** → выберите репозиторий.
   Render прочитает `render.yaml` и сам предложит создать сразу два сервиса:
   `cheat-bot` и `sponsor-checker`.
3. Подтвердите — Render создаст оба сервиса, но их ещё нужно донастроить (см. шаг 4-5 ниже),
   т.к. секретные переменные (`sync: false`) не заполняются автоматически.

### Вариант Б — вручную, по одному сервису

**Сервис 1 — чекер-бот** (создайте и настройте его первым, он проще):

1. **New** → **Web Service** → тот же репозиторий.
2. Start Command: `python checker_bot.py` (Build Command как обычно: `pip install -r requirements.txt`).
3. Переменные окружения:
   - `CHECKER_BOT_TOKEN` — токен **второго**, отдельного бота от @BotFather;
   - `CHECKER_SECRET` — придумайте длинную случайную строку (например, из `openssl rand -hex 32`);
   - `CHECKER_ADMIN_IDS` — по желанию, ваш Telegram ID, чтобы использовать команду `/channels`.
4. Деплой. После запуска скопируйте публичный адрес сервиса — что-то вроде
   `https://sponsor-checker-xxxx.onrender.com`.

**Сервис 2 — основной бот:**

1. **New** → **Web Service** → тот же репозиторий.
2. Start Command: `python bot.py`.
3. Переменные окружения:
   - `BOT_TOKEN` — токен основного бота;
   - `ADMIN_IDS` — ваш Telegram ID;
   - `CHECKER_URL` — адрес чекер-бота из предыдущего шага (без слэша на конце);
   - `CHECKER_SECRET` — **тот же самый** секрет, что вы задали чекер-боту;
   - остальные — по желанию, см. `.env.example`.
4. Деплой.

После обоих деплоев в логах основного бота должно появиться что-то вроде
`Чекер-бот запущен: @your_checker_bot` — это значит, что он смог связаться с
чекер-ботом и узнал его username. Если вместо этого видите предупреждение
«Не удалось узнать username чекер-бота» — проверьте `CHECKER_URL`/`CHECKER_SECRET`
и что оба сервиса запущены.

Проверить, что каждый сервис жив, можно, открыв в браузере его адрес — оба
должны отвечать `OK` на `/` и `/health`.

⚠️ На бесплатном плане Render диск не постоянный — при каждом передеплое файлы
баз `cheats.db` и `checker.db` создадутся заново (все читы и админы, кроме
заданных в `ADMIN_IDS`, потеряются; чекер-бот заново узнает статус админства в
каналах при первом же запросе). Если это важно, подключите платный
Persistent Disk в Render для обоих сервисов, либо переключитесь на внешнюю БД.

## Анти-засыпание через UptimeRobot

Бесплатный Render Web Service «засыпает» примерно через 15 минут без входящих
HTTP-запросов — это касается **обоих** сервисов, и если уснёт чекер-бот, у
пользователей перестанет проходить проверка подписки. Поэтому мониторить нужно
оба адреса:

1. Зарегистрируйтесь на [uptimerobot.com](https://uptimerobot.com) (бесплатно).
2. **Add New Monitor** → Monitor Type: `HTTP(s)`.
3. URL: `https://<основной-бот>.onrender.com/health`.
4. Повторите то же самое вторым монитором для `https://<чекер-бот>.onrender.com/health`.
5. Monitoring Interval: 5 минут для каждого.
6. Сохраните — теперь UptimeRobot будет пинговать оба бота и не давать им уснуть.

## Первый запуск бота

1. Откройте бота в Telegram под своим (админским) аккаунтом → `/start`.
2. Увидите инлайн-панель админа. Нажмите «➕ Добавить чит», укажите название и пришлите текст/файл/фото/гифку.
3. Бот выдаст персональную ссылку вида `https://t.me/ваш_бот?start=токен` — её и раздавайте пользователям.
4. Обычный пользователь, перейдя по ссылке, получит чит и сможет поставить 👍/👎.
5. Добавить нового админа: кнопка «👤 Добавить админа» → укажите его числовой ID (или перешлите его сообщение) — либо сразу `/addadmin 123456789`.

## Локальный запуск (для теста)

```bash
pip install -r requirements.txt
export BOT_TOKEN="..."
export ADMIN_IDS="123456789"
python bot.py
```

## Новое: спонсоры и обязательная подписка

Теперь у бота есть система спонсорских каналов: обычный пользователь (не админ) должен
быть подписан на все активные спонсорские каналы, иначе на **любую** команду/кнопку бот
будет отвечать сообщением с просьбой подписаться и кнопкой «✅ Я подписался, проверить».

### Как добавить спонсора

Есть два способа:

1. **Через админа напрямую** — в админ-панели кнопка «🔗 Добавить свою ссылку». Админ сам
   проходит все шаги (канал → рефералка → название кнопки).
2. **Выдать доступ внешнему спонсору** — команда `/give <id>` (или кнопка «🎁 Выдать доступ
   спонсору»). Это НЕ делает человека админом бота — он просто получает право один раз
   добавить свою спонсорскую кнопку. Дальше он сам пишет боту `/start`, и бот проведёт его
   по шагам:
   1. Добавить бота-проверяльщика (чекер-бота) администратором в свой канал (инструкция доступна по кнопке
      «📖 Инструкция как добавить бота», текст редактируется в админ-панели).
   2. Переслать боту любой пост из канала (или отправить его `@username`) — так бот
      определяет канал и проверяет, что действительно добавлен туда администратором.
   3. Прислать отдельную пригласительную ссылку (рефералку) — именно её увидят пользователи
      на инлайн-кнопке.
   4. Придумать название для кнопки — как её назвать, решает сам спонсор (или админ, если
      ссылку добавляет он).

   После этого доступ считается использованным — чтобы дать человеку право добавить ещё
   одну ссылку, выдайте `/give <id>` повторно.

Важно: в канал спонсора администратором добавляется чекер-бот, а не основной бот
с читами. Ему не нужны специальные права — только сам факт, что он администратор,
чтобы иметь возможность проверять подписчиков (`getChatMember`). Постинг, удаление
сообщений и т.д. включать ему не нужно.

Список всех спонсоров и удаление — кнопка «📃 Список спонсоров» в админ-панели.

## Новое: меню для обычных пользователей

После подтверждения подписки пользователь видит главное меню с двумя кнопками:

- **🎮 Читы** — список всех добавленных читов инлайн-кнопками; при нажатии бот присылает
  сохранённый текст/файл/фото/гифку и кнопки 👍/👎 (как раньше по персональной ссылке).
- **ℹ️ Информация** — свободный текст (кто владелец, правила и т.д.), редактируется в
  админ-панели кнопкой «✏️ Инфо для юзеров».

Оба текста («Информация» и «Инструкция для спонсоров») хранятся в базе данных и правятся
прямо из Telegram, без правки кода.

## Новые команды админа

| Команда | Что делает |
|---|---|
| `/give <id>` | выдаёт пользователю право один раз добавить спонсорскую ссылку |

Всё остальное (добавление своей ссылки, список спонсоров, редактирование текстов) доступно
через кнопки в `/menu`.
